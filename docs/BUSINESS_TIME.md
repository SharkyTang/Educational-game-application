# 营业时间第一版与后续路线

现金收款第二版接入后，当前3D存档使用v12，并完整保留本文的营业时间规则。本文的v9迁移记录保留为营业时间版本的历史；当前有限钱箱见 [现金收款第二版](./CASH_PAYMENT.md)，布局、扩建和旧档兼容说明见 [店铺成长与自由装修](./SHOP_RENOVATION.md)，社区现金帮助规则见 [英国街头邻居](./STREET_NEIGHBOURS.md)。

更新日期：2026-08-31。

本文记录已实现的第一版营业时间机制、v9存档兼容规则及分阶段计划。集成版本的单测、构建和浏览器回归已通过，具体证据与未验证边界见文末；用户试玩手感仍需反馈。

本版将第一人称 3D 小店从“每天三位付费顾客后结束”改为“营业时间内持续接客，到点停止接新客，安全收尾后日结”。[S1 首日记录](./S1_FIRST_DAY.md)中的每日三单、固定订单及对应验收数字是历史基线，不代表本版行为。商品、采购和库存继续沿用[自选进货](./PRODUCT_SHOPPING.md)、[商业街送货](./STREET_DELIVERY.md)与[空箱回收](./CRATE_RECYCLING.md)的现有规则；支付金额与找零逻辑继续沿用[现金收款](./CASH_PAYMENT.md)，本版只调整它与营业钟的衔接。

## 第一版范围

第一版包含营业钟、持续客流、打烊收尾、学习暂停及安全存档；仍然同时只有一位顾客。天空、日照、路灯和店内灯光的昼夜变化属于下一版，本版不宣称已经接入。

### 1. 一天如何推进

| 阶段 | 游戏时间 | 规则 |
| --- | --- | --- |
| 开店准备 | 08:30，冻结 | 可以进货、签收、搬运、上架和近看商品；准备好后手动开门，不自动催促开店。 |
| 正式营业 | 09:00—19:00 | 开门后累计有效营业时间；每天顾客总数不设三单上限，按库存及接待速度持续来客。 |
| 打烊收尾 | 到达19:00，或确认提前打烊 | 停止接新顾客和新采购；保留当前顾客、未完成交易及已付款配送，允许完成收尾。 |
| 日结休息 | 满足收尾条件后由玩家确认 | 汇总已发生的经营结果，现金和未售库存进入次日；次日回到08:30准备阶段。 |

完整营业时段为420,000毫秒，即7分钟**有效营业时间**。09:00到19:00共600个游戏分钟，按累计有效时间线性换算，显示时间不会超过19:00。计时与渲染帧率解耦，不按现实钟点推算店内时间。

18:30提醒即将停止接客，19:00进入收尾。准备阶段也可确认“今天不营业，结束准备”，无需为了结束一天而虚构顾客或收入。

[PRD第6.2节](./PRD.md#62-单次学习闭环)中的普通营业日8—10分钟继续作为待试玩验证的节奏目标。准备、学习保护、暂停及打烊收尾可以延长实际游玩时间；7分钟不是强制退出倒计时，也不表示每位玩家实际都能在10分钟内完成一天。

### 2. 顾客持续到来，但不同时挤进店

- 每天人数不封顶；“不封顶”不等于同时出现无限顾客，也不保证每天固定服务人数。
- 同时仅一位顾客。上一位真正离店后，才开始8—12秒的来客间隔；收款成功但尚未离店时不会立即生成下一位。
- 间隔由可保存的随机种子生成，使用有效游戏时间推进。刷新或重复读取存档不能重新抽取间隔，也不能生成重复顾客。
- 有可售货架商品时才继续接客；缺货时停止生成新顾客，但营业钟继续走。玩家可以补货，也可以确认提前打烊，不因零库存被迫永久等待。
- 顾客继续使用现有商品选择与付款规则，不因取消三单限制而复制商品、重置购物清单或重发收入。
- 第三位顾客离店不再自动进入日结。第一版不额外新增“前三位教学顾客”系统。

### 3. 英语学习保护与暂停

| 玩家状态 | 营业钟与来客等待 | 说明 |
| --- | --- | --- |
| 正常走动、搬箱、上架、补货 | 推进 | 保留经营节奏。 |
| 普通收银、扫码、付款操作，含现金找零面板 | 推进 | 现金面板暂停角色动作但不自动冻结营业钟；到点不会强行终止订单。 |
| Tab释放鼠标，或收银自动释放鼠标 | 推进 | “鼠标可点击”和“暂停营业”是两件事。 |
| 暂停菜单、进货/扩容/日结等管理面板 | 暂停 | 面板返回后恢复既有控制方式，不自动强制锁定鼠标。 |
| 商品近看学习 | 暂停 | 可以观察模型、阅读标签并主动播放词汇发音。 |
| 主动重听、请求慢速重说 | 暂停 | 在对应学习播放期间保护时间；结束或退出后恢复，不能永久卡住营业钟。 |
| 页面隐藏或窗口失焦 | 暂停 | 回到游戏不补算后台时间，控制与音频按安全恢复规则处理。 |

多个暂停原因可以重叠；解除其中一个原因，不应让仍处于其他暂停状态的游戏偷偷走时。自动播放日常顾客台词不等于玩家主动进入学习保护。

本版不增加顾客耐心或独立找零倒计时，也不把听得慢、重听或学习暂停作为失败或罚款依据。这些操作不构成口语评测或英语掌握证明。

### 4. 打烊不等于立即结算

到达19:00自动进入收尾阶段。提前打烊必须由玩家确认，取消确认不会改变营业状态。收尾阶段不再生成新顾客，也不接受新采购订单。

仍然允许：

- 完成当前顾客的购物、扫码和付款，让顾客正常离开；到点不清空交易。
- 安全取消尚未完成的订单，按现有库存规则归还商品，不丢货、不重复归还、不误记收入。
- 签收已经付款的配送，搬运、上架和整理现有库存。
- 使用空箱回收点；空箱未回收本身不应阻塞日结。

只有同时满足以下条件，才可确认日结：

1. 当前没有顾客，包括尚未走完离店路线的顾客。
2. 没有待签收的已付款配送。
3. 没有未完成交易中的待付款商品。

其中“没有待付款商品”不要求把货架和货箱中的未售库存卖空。被取消订单中的商品必须先回到合法库存位置；不能通过清空顾客状态绕过货物归属校验。

零单日允许正常收尾和进入下一天，日期与累计日结总天数照常记录；但咖啡店“首次有收款的营业日结”只统计至少成功收款一单的日结，零单日不能满足该条件。即使随后已达到Lv2，仍须完成一次有收款的日结。实际成功订单数、经验和收入不凭空增加。普通货架扩容继续遵守现有资金门槛，不新增英语门槛。

日结只汇总已经发生的收款、成本、采购、扩容及回收记录，不再次发钱；次日不补发本金。打烊不会把未付款订单改成已付款，也不会对已完成付款重复退款或重复收款。

### 5. 刷新和旧档恢复

v9存档在同一份完整安全快照中保留：

- 当前营业日、准备/营业/收尾/已结算阶段，以及累计有效营业时间。
- 来客等待进度及生成间隔所需的确定性状态。
- 当前顾客身份、购物清单、持有商品、购物/离店阶段及未完成交易，包括暂收现金和已选零钱。
- 对应现金、商品归属、配送、日结及成就依据。

营业中刷新后继续已保存的店内时间和顾客进度，不重置为09:00、不跳到19:00、不补算离线时间、不重新生成已付款交易。来客等待中刷新也应继续剩余等待。

v3—v8先按各自原版本完整校验，再迁移到独立v9主存档和备份；旧键保持原样，沿用跨版本写入锁与迁移源冲突检查。迁移保留原现金、库存、顾客、未签收配送和日结；v8现金付款方式、暂收与找零状态原样恢复，v7及更早的旧交易和活跃顾客按刷卡兼容，不发放额外本金或奖励。

旧版没有营业时长，按以下明确规则初始化，而不是从已服务人数估算时间：

| 旧档阶段 | v9恢复行为 |
| --- | --- |
| 准备中 | 保留准备阶段，08:30冻结。 |
| 营业中 | 保留营业和顾客阶段，从09:00接续；即使旧档已经三单，也不自动关门。顾客已离店时按保存种子安排下一次来客。 |
| 已日结 | 保留原日结；界面标明旧版未记录时间，不伪造19:00。开始次日后回到08:30准备。 |

旧日结的三单目标与金额保留为历史，新营业日不设人数目标。损坏、篡改或无法迁移的数据不能静默覆盖最后有效快照；旧版仍按原有规则校验，不能用新版“不封顶”字段伪装成合法旧档。

第一版不包含离线收益、云存档、跨设备账户或旧2D存档的直接复用。

## 后续开发路线

以下顺序以前一阶段验收和真实试玩反馈为进入条件，不代表已经承诺工期或自动扩大本轮范围。

| 阶段 | 目标与交付 | 验收重点 | 本阶段非目标 |
| --- | --- | --- | --- |
| 第二版：昼夜视觉 | 用第一版同一营业钟驱动晨光、白天、傍晚和夜色；接入太阳方向、天空渐变以及路灯/店内灯光变化。 | 时间和画面同步，暂停/刷新后天色一致；变化平滑；夜晚仍看得清商品、英文标签和收银台；在现有试玩设备上检查性能与视觉舒适度。 | 天气、季节、多人队列；不为视觉效果改动营业时长或交易结果。 |
| 第三版：客流与经济调优 | 记录实际完成一日所需时间、服务人数、缺货等待及补货/学习体验；据此调整日长、来客间隔、成本和成长节奏，必要时加入有限的忙闲时段。 | 慢速学习者能够从容完成一日；熟练玩家有持续经营空间；避免一天迅速耗尽所有成长目标；变化有可重复的试玩和数据依据。 | 未经验证的固定最佳参数、强制耐心惩罚、完整财务模拟；不把经营效率当成英语能力。 |
| 第四版：可选多人购物与队列 | 若单人接客已稳定且用户仍希望提高经营密度，再引入有容量上限的同时购物和排队，明确顾客、商品预占与收银归属。 | 最后一件商品不被多人重复拿走；队列不会堵死；语音不互相覆盖；打烊、取消、刷新均可恢复；性能可接受。 | 无限同时人数、多雇员或自动收银；不因“无限顾客”措辞默认纳入。 |
| 第五版：可选天气与季节 | 核心日循环稳定后，再按体验需要增加天气氛围和季节变化；是否影响客流或商品需求另行确认。 | 氛围变化不降低可读性；存档可复现；不会阻断学习或破坏经济平衡；资源成本与性能可控。 | 完整气象模拟、现实日历同步、农作物/保质期等新经营系统。 |

建议用户先试玩第一版，重点反馈“7分钟有效营业是否合适”“两位顾客之间够不够补货”“学习时是否安心”“打烊收尾是否清楚”。第二版完成后再确认天色与灯光的视觉效果，避免把经营节奏和视觉反馈混成一次难以判断的调整。
