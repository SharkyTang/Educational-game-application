# 现金收款第一版

本文记录英镑现金第一版的点击找零、全程金额提示与可恢复收款流程，以及v8历史存档设计，不引入真实支付接口。当前营业规则已接入v9 [营业时间第一版](./BUSINESS_TIME.md)：09:00—19:00为7分钟有效营业，每天顾客不封顶、同时一位，不再在三单后结束。找零金额与提交规则保持不变；普通找零时营业钟继续，主动重听/慢读与后台暂停，到点不会打断当前付款。

## 玩家流程

1. 顾客进店时确定本次购物清单、付款方式及交款金额；之后补货、重听或刷新不会重新抽取。
2. 新游戏第一位顾客仍刷卡，第二位顾客用现金作引导。后续顾客按存档中的随机种子与顾客编号稳定混合刷卡和现金，付款方式不改变购物清单。
3. 必须扫描完全部商品。刷卡客人继续在收银台按 E 收款；现金客人按 E 或点击小票中的现金入口打开找零面板。
4. 核对应付、顾客交付与应找金额，点击“收下现金”。此时仅暂收，尚未算营业收入。
5. 点击钱箱面额加入找零托盘；点击托盘里的钱撤回，或清空重选。提示会说明还差或多出多少，任何总额正确的组合都有效。
6. 找零金额正确才可确认。顾客刚好付清时，收下现金后直接确认，无需选择零钱。确认后商品售出、资金净增本单售价，顾客道谢离开。

例如牛奶 £1.60 与奶酪 £2.75 合计 £4.35，顾客交 £5，找零 £0.65；50p + 10p + 5p 与 20p + 20p + 20p + 5p 都应被接受。本单营业收入为 £4.35，而不是交来的 £5。

## 钱箱、提示与边界

- 所有金额继续使用整数便士（pence），1 英镑为 100 便士；展示时才格式化成英镑。
- 常用控制是 5p、10p、20p、50p、£1、£2、£5、£10；1p、2p 收在可展开的小额硬币区。£1、£2 标为硬币，£5、£10 标为纸币。
- 面板使用标有面额的游戏控制，不是可流通钞票图像，也不模拟验钞。
- 零钱库存暂不限量，但一笔选择最多 100 枚/张，避免异常输入或无限 DOM 增长；这不是钱箱总库存上限。
- 暂不产生交款不足的正常订单，拒绝非法交款与面额；不加入独立找零倒计时、罚款、小费、大额兑换、混合付款、退货或银行账户。营业钟按上述时间版规则推进，不等于对当前现金订单限时。
- 找零面板暂停玩家移动和顾客动作，释放鼠标。Esc 或“暂时离开”关闭面板，保留本单，不自动重新捕获鼠标。
- “小店资金”仍是现有经营总余额，刷卡和现金都进入同一余额；实体钱箱的面额库存尚未建模。

## 存档与一致性

支付中间状态由领域层与整份存档共同持有，不另存在 DOM 或临时 UI 变量中。收钱、添加/撤回零钱都经规则校验并保存；刷新或关闭面板之后可继续同一笔单。

v8 在 v7 回收存档基础上加入当前支付状态与交易支付明细。v3–v7 先按原版本校验再迁移，旧记录和旧活跃顾客按刷卡兼容；原金额、物品、已扫描记录、回收与日结保留，不重新发放本金。旧存档键不覆盖、不删除，跨版本继续共用同一写入锁。

上述为现金第一版的v8设计。当前v9迁移先验证原版本，保留v8已有现金付款、暂收金额和零钱托盘，再补充营业时间字段；不会把v8现金顾客改回刷卡，也不会补收或补发钱。时间迁移与当前日结条件以 [营业时间与旧档恢复](./BUSINESS_TIME.md#5-刷新和旧档恢复)为准。

现金确认与原刷卡共用一次性销售规则：唯一交易记录、资金净增、商品变为已售、清理扫描与支付状态、顾客离店必须一起成功。旧 PAY 命令不能绕过现金找零。取消未完成订单会归还商品、退回暂收现金并清除支付状态；若商品无法安全归还，整单保持不变。

日结仍只汇总已完成交易，不把暂收金额或已选零钱作为收入，不重复发钱。

## 英语与声音

新增 4 条现金请求及 £5、£10、刚好付清共 3 条交款短句，每条有男女两套本地英式合成录音。字幕、重听与实际播放来自同一语料记录；原 56 段顾客录音和旧版 8 段短句不改。

现金请求只给现金顾客播放，刷卡请求仍使用原池。交款额恰好等于商品总价、又不是 £5/£10 时，用通用的“I have the exact amount.”，不拼接无法验证的数字音频。

音频可重听，失败或音量为 0 时仍可查看字幕并完成操作。不请求麦克风，不使用运行时 LLM，不把听过配音或有提示地找零计为独立语言掌握。

## 验收

验证命令为 `npm run check` 和 `npm run test:e2e`。专项检查包括：未扫描/未收钱不得确认、刚好付清、找多找少、不同正确组合、非法面额、100枚上限、重复收款、取消成功和失败、关闭/Esc/刷新恢复、旧档迁移、跨标签写入保护、刷卡回归与日结一致性。浏览器检查还包含鼠标释放、面板期间不移动、窄窗口能滚动至确认按钮，以及语音与字幕对应。
