# 现金收款与钱箱

第四版加入实体抽屉、可见教学纸币与硬币、顾客交款区和找零托盘。扫描完成后打开现金收银，可直接点钱收款、选取和撤回找零；面额按钮和键盘操作继续保留。具体范围、兼容边界与本轮验收见 [实体钱箱与可见货币](./CASH_VISUALS.md)。第四版只投影现有现金状态，不引入新存档版本或第二套资金。当前备用金、退款与盘点的入口是店内电脑「营业 / 日结 → 现金管理」；下面前三版中的旧管理入口与营业时长属于历史记录，以当前 [店内电脑与循环经营](./SHOP_COMPUTER.md) 为准。

第三版接在设备经营 v13 之后，历史存档基线使用 v14，加入开店备用金调配、当天整单退款／撤销，以及打烊钱箱盘点。下列前三版说明与验收数字保留各自历史口径，当前营业规则见 [营业时间](./BUSINESS_TIME.md)。

## 第三版玩家流程

### 开店备用金

准备开店、双手空闲且没有未完成付款时，可在管理菜单的现金管理区填写每种面额的数量并确认配置。钱箱与保管余额之间按总面值调配，可以调整面额组合，也可把部分钱留在保管余额。新钱箱不能超过两者现有合计；每次调配保留日期、交易边界、钱箱快照和保管余额。

教学备用金仍从 £31.60 开始，保管余额初始为零。二者是现金操作的记录，不是第二份可消费的小店资金；配置或换面额不会增加经营收入。营业中不能配置，当前顾客手里的暂收款也不能当作备用金。

### 退款与撤销已完成交易

在当天日结前、顾客已离开且双手空闲时，从当天小票选择“整单退货”或“撤销交易”，核对原付款渠道和金额后再次确认。两种操作都退回整单商品和原售价，区别作为原因记录；付款前的取消订单仍沿用原流程。

- 现金订单按原售价从现有钱箱凑出退款面额；刷卡订单走游戏内原渠道冲回，不扣钱箱。经营余额和现金面额不足时拒绝本次操作。
- 商品优先回可用货架或安全货箱，之后可以再次售卖。放不下时整单不变，先腾出货位再重试。
- 原始小票保留，追加唯一退款记录；不删单、不改原成交金额，同一小票不能重复退款。
- 日结同时显示原销售额、退款额和净营业收入；退回商品的成本从已售成本中冲回。经营等级和销售成就按未退款的有效订单计算，反复买退不会累积经验。
- 第三版支持当天未日结整单，暂不包括跨日退货、部分退货、损坏商品报废、混合付款或真实银行接口。

### 打烊钱箱盘点

打烊收尾并等顾客离开后，逐面额填写实点数量。界面显示账面应有金额、实点金额和长短款；即使总额相同，只要面额组合不同，也会记录面额差异。存在差异必须填写原因或备注。

提交后保留当时的应有与实点快照、差额、备注及交易边界。盘点只记录核对结果，不按输入凭空补钱或扣钱。盘点之后再退款会使旧盘点标为过期，需要重新核对；重复复核保留历史，不覆盖旧记录。旧日结流程仍可继续，未盘点与有差异会明确显示，不伪称已经对平。

现金管理沿用暂停面板的移动和营业钟暂停。配置与盘点的未提交输入属于界面草稿；确认成功的调配、退款和盘点才进入完整存档，刷新可恢复。

## 第三版存档与一致性

v14 追加 `cashReservePence` 与按发生顺序保存的 `cashJournal`，现金事件包含备用金调配、退款和盘点。原有固定教学基准、有限钱箱追踪起点、实收／实找面额和来源标记继续保留。校验按交易边界重放销售与现金事件，同时核对当前钱箱、保管余额、有效商品归属、小店资金和日结；同一商品退回后再次成交不会被误判为复制商品。

v13 及更早存档先按各自原版本校验，再迁移到 v14。旧档没有的退款和现金事件从空开始，保管余额为零，历史日结补充零退款和原净收入；原钱箱、暂收款、找零托盘、设备、第二次扩建、库存、订单、回收、社区帮助和营业时间原样保留。旧版本携带新版审计字段会被拒绝，不能把退款账本换个版本号绕过校验。

主存档、上一有效备份和旧版本来源分别保留，迁移不改写旧键，跨版本继续共用写入锁。若当前版本损坏而回退旧版本，会说明近期退款、调配与盘点可能丢失。这里的校验用于本地数据一致性，不是数字签名或防止替换本地存档的安全机制。

## 第一、二版基础流程与历史说明

第二版在原有英镑点击找零上加入有限面额库存、v12新现金状态与交易的实际交款组合、零钱不足处理，以及现金/刷卡日结拆分。下述第二版基准与迁移说明保留历史口径，第三版新增操作以前述章节为准；没有真实支付接口。营业规则沿用v9 [营业时间第一版](./BUSINESS_TIME.md)：09:00—19:00为7分钟有效营业，每天顾客不封顶、同时一位。普通找零时营业钟继续，主动重听/慢读与后台暂停，到点不会打断当前付款。

## 玩家流程

1. 顾客进店时确定本次购物清单、付款方式及交款金额；之后补货、重听或刷新不会重新抽取。
2. 新游戏第一位顾客仍刷卡，第二位顾客用现金作引导。后续顾客按存档中的随机种子与顾客编号稳定混合刷卡和现金，付款方式不改变购物清单。
3. 必须扫描完全部商品。刷卡客人继续在收银台按 E 收款；现金客人按 E 或点击小票中的现金入口打开找零面板。
4. 核对应付、顾客交付与应找金额，点击“收下现金”。此时仅暂收，尚未算营业收入。
5. 点击钱箱面额加入找零托盘；每个按钮显示扣除托盘预留后的剩余数量，用完即禁用。点击托盘里的钱可撤回，也可清空重选。
6. 若完整钱箱仍能找零、但当前组合走入死路，提示会要求撤回或清空；不会误报整个钱箱没零钱。
7. 若完整钱箱确实无法凑出应找金额，可使用两句明确的双语处理：“请给刚好金额 / Could I have the exact amount, please?”或“可以刷卡吗 / Could you pay by card, please?”。原暂收现金先退回，资金和钱箱都不改变。
8. 找零金额正确且面额库存足够才可确认。顾客刚好付清时，收下现金后直接确认，无需选择零钱。确认后商品售出、资金净增本单售价，交款面额进入钱箱、找零面额同时扣除，顾客道谢离开。

例如牛奶 £1.60 与奶酪 £2.75 合计 £4.35，顾客交 £5，找零 £0.65；50p + 10p + 5p 与 20p + 20p + 20p + 5p 都应被接受。本单营业收入为 £4.35，而不是交来的 £5。

## 钱箱、提示与边界

- 所有金额继续使用整数便士（pence），1 英镑为 100 便士；展示时才格式化成英镑。
- 常用控制是 5p、10p、20p、50p、£1、£2、£5、£10；1p、2p 收在可展开的小额硬币区。£1、£2 标为硬币，£5、£10 标为纸币。
- 面板使用标有面额的游戏控制，不是可流通钞票图像，也不模拟验钞。
- 新档使用有限教学备用零钱：1p、2p、5p、10p各20枚，20p 15枚，50p、£1各10枚，£2 5枚，£5与£10纸币为0张，共120枚/张、面值£31.60。这个面值只表示可找零钱件，不是额外经营资金。
- 全新v12现金状态与交易会把顾客实际交付的纸币/硬币数组和合计金额同时保存；现金成交后才能进入钱箱。旧档从合计生成的规范数组会标记为“未实际记录”，不冒充历史实物组合；刷卡交易的交款和找零数组必须为空。
- 一笔交款或找零最多100枚/张。算法在有限库存内寻找稳定的最少枚数组合；没有组合时不允许透支、负库存或凭空制造零钱。
- 暂不产生交款不足的正常订单，拒绝非法交款与面额；不加入独立找零倒计时、罚款、小费、大额兑换、混合付款、退货或银行账户。营业钟按上述时间版规则推进，不等于对当前现金订单限时。
- 找零面板暂停玩家移动和顾客动作，释放鼠标。Esc 或“暂时离开”关闭面板，保留本单，不自动重新捕获鼠标。
- “小店资金”仍是唯一经营总余额，刷卡和现金都只按商品售价进入该余额。教学钱箱的£31.60备用零钱及后续面额变化不作为第二份可消费余额，也不重复计入收入。

## 存档与一致性

支付中间状态由领域层与整份存档共同持有，不另存在 DOM 或临时 UI 变量中。收钱、添加/撤回零钱都经规则校验并保存；刷新或关闭面板之后可继续同一笔单。

v8 在 v7 回收存档基础上加入当前支付状态与交易支付合计。现金第二版使用当前v12：新增交款/找零面额及其“是否真实记录”标记、当前钱箱、钱箱追踪起点和固定教学基准快照。追踪起点之后的每笔现金交易都可从基准按顺序重放，结果必须与保存的钱箱完全一致；暂收、选币与取消不会提前改变钱箱。

读取v11及更早存档时先按原版本严格校验，再迁移到v12。原资金、库存、订单、营业时间、布局、扩建、社区帮助、现金暂收和零钱托盘保持不变；历史交易不会倒推消耗刚建立的有限钱箱。钱箱始终使用固定的£31.60教学基准，并从明确的交易边界开始追踪。若旧托盘所选数量超过新钱箱现有库存，迁移仍保留这笔未完成选择，但不能直接确认：只要完整钱箱仍可找足，玩家就需撤回或清空后重选；仅当完整钱箱确实无法凑出应找金额时，才可请求刚好金额或改刷卡。迁移不会补造零钱，也不给小店资金加钱。旧键不覆盖、不删除，跨版本继续共用同一写入锁。时间迁移见 [营业时间与旧档恢复](./BUSINESS_TIME.md#5-刷新和旧档恢复)。

v8–v11只记录交付和找零合计，没有实际纸币/硬币组合。迁移为严格结构校验生成的规范数组不代表历史上实际递交或找回的面额；因此旧交易收据只显示金额合计，并明确标注“旧版未记录面额”。新交易按交款与找零分别保存记录标记：全新的现金交易两部分都显示实际面额；迁移中的旧待付款在确认后，旧交款仍标为未记录，而本次实际找出的零钱可以照常显示。

现金确认与原刷卡共用一次性销售规则：唯一交易记录、资金净增、商品变为已售、清理扫描与支付状态、顾客离店必须一起成功。旧 PAY 命令不能绕过现金找零。取消未完成订单会归还商品、退回暂收现金并清除支付状态；若商品无法安全归还，整单保持不变。这里的结构校验、账本重放与写入锁用于本地数据一致性，不是加密、数字签名或防止玩家替换本地存档的安全机制。

日结仍只汇总已完成交易，不把暂收金额或已选零钱作为收入，不重复发钱。界面从同一交易账本派生显示现金单数/金额与刷卡单数/金额，并显示当前教学钱箱各面额数量；两种付款收入相加必须等于当日营业收入。

## 英语与声音

新增 4 条现金请求及 £5、£10、刚好付清共 3 条交款短句，每条有男女两套本地英式合成录音。字幕、重听与实际播放来自同一语料记录；原 56 段顾客录音和旧版 8 段短句不改。

现金请求只给现金顾客播放，刷卡请求仍使用原池。交款额恰好等于商品总价、又不是 £5/£10 时，用通用的“I have the exact amount.”，不拼接无法验证的数字音频。

音频可重听，失败或音量为 0 时仍可查看字幕并完成操作。不请求麦克风，不使用运行时 LLM，不把听过配音或有提示地找零计为独立语言掌握。
