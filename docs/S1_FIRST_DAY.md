# S1：一间小店的完整首日

更新：2026-08-31。当前范围为首日经营纵向切片，以及 S0 试玩暴露的语音、鼠标和扩容可发现性修复。本轮已完成下述本地功能验证；声音自然度、正式美术、跨设备与学习效果不由自动化结果推定。

[试玩入口](http://localhost:4200/) · [PRD v0.3](./PRD.md) · [素材与许可](./ASSET_SOURCES.md) · [历史 S0 记录](./S0_3D_IMPLEMENTATION.md)

## 本轮解决什么

- 顾客由仅显示文字，改为入店、结账和付款后自动说出预制台词。
- 核心台词和搭配使用本地音频；鼠标可单独释放，重听按钮不再要求玩家先进入暂停菜单。
- 进货、营业/日结、普通扩容有显式入口和快捷键，不再把唯一升级藏在暂停菜单深处。
- 从免费测试货改为新档 £12 本金与空货箱，完成真实扣款采购、三单营业、日结、扩容和次日续营。
- 新 v4 存档记录采购与营业日，并保留、校验迁移旧 v3 进度；不删除或覆盖旧 2D 存档。

仍然是一间店、两类商品、一次一位顾客和固定订单，不是完整超市模拟器、自由英语对话系统或研究版 P0。

## 启动与固定地址

普通运行只需要 Node.js 22 或更高，不需要安装 Python、下载语音模型或申请 API 密钥。

```sh
npm install
npm run build
npm run play
```

打开 [http://localhost:4200/](http://localhost:4200/)。4200 是 `dist` 的生产构建预览，只监听本机；端口冲突会报错，不自动跳到其他端口。修改代码、文案或音频后，先重新 `npm run build`，再刷新页面；只刷新不能更新旧构建。

开发服务为 `npm run dev:3d`，地址 [localhost:4199](http://localhost:4199/)，支持热更新。不要使用之前其他项目占用的 4174 判断当前游戏。

浏览器将 `localhost:4200`、`127.0.0.1:4200` 和 4199 分别视为独立来源，存档不会自动互通。需要搬进度时使用游戏的 JSON 导出/导入，不通过清理站点数据处理版本问题。

## 首日推荐路线

这条路线以**新建 S1 存档**为前提。已有 S0 进度会保留其原现金与商品，不会强制清空来套用示例。如要重新体验开场，应先导出进度，再由玩家明确确认重新开始。

| 阶段 | 玩家操作 | 应看到的经营结果 |
| --- | --- | --- |
| 准备 | 开始第一天，按 B 看进货单 | £12 本金、两个空货箱；尚未营业 |
| 采购 | 推荐选择 3 份组合，确认 £6.90 | 牛奶和面包各 3 件进入对应货箱，现金 £5.10 |
| 搬运与认识 | E 抱箱，F 近看，分别听单词与搭配 | 实物与词义对应；近看不会复制或消耗货物 |
| 上架 | 走到对应货架，逐件摆放；G 在安全点放箱 | 箱内数量减少、货架数量增加，商品 ID 不变 |
| 开门 | 走到门口营业牌，按 E | 首位顾客自动进入并问候 |
| 第一单 | 顾客取一份牛奶和面包，到台前后逐件扫描、收款 | 成功付款一次收入 £4，现金 £9.10；之后道谢离开 |
| 后续两单 | 上一位离店后，后续顾客自动接续 | 完成三位付费顾客；当前不出现多人队列 |
| 日结 | 等第三位顾客离店，打开“营业 / 日结”并确认 | 记录当日收入、成本与现金；不再发一遍销售收入 |
| 扩容 | 按 U 或点“扩容”，花 £8 | 每类货位 4→8，现金 £9.10；不会凭空出现库存 |
| 次日 | 在管理界面开始次日 | 现金、未售库存与已购容量保留；重新准备与开门，不再送本金 |

表中的顺序只是首日引导。普通扩容在准备、营业或日结后都只检查资金与未重复购买，**不要求完成三单、日结或英语任务**。先花钱扩容会减少可用于进货的现金，可以改买较小组合；不能把推荐流程写成隐藏解锁门槛。

## 采购、日结与升级口径

所有金额用整数便士存储，界面显示英镑；游戏内金额不涉及真实支付。

| 商品 | 单件进价 | 单件售价 |
| --- | ---: | ---: |
| milk / 牛奶 | £0.90 | £1.60 |
| bread / 面包 | £1.40 | £2.40 |

每份组合含牛奶 1 件、面包 1 件，可选择 1 / 3 / 6 份，价格分别为 £2.30 / £6.90 / £13.80。新档 £12 不足以购买 6 份属于资金不足，不是英语锁。采购要检查货箱和暂存空间；相同采购单不能被重复扣款或重复发货。日结后先开始次日，才能再采购。

每位顾客固定买两件，合计 £4。扫描只改变“已扫描”状态，付款成功才一次性计入交易和现金；取消或失败不能把未付款货物算为已售。

新档购买 3 份、全部卖完三单、未提前扩容且无额外采购时：

| 项目 | 计算 | 结果 |
| --- | --- | ---: |
| 采购支出 | 3 × (£0.90 + £1.40) | £6.90 |
| 营业收入 | 3 × (£1.60 + £2.40) | £12.00 |
| 已售商品成本 | 实际售出的 3 份商品成本 | £6.90 |
| 毛利 | 收入 − 已售成本 | £5.10 |
| 升级前现金 | 首日本金 £12 − 采购 £6.90 + 收入 £12 | £17.10 |
| 普通扩容 | 一次性投资 | £8.00 |
| 升级后现金 | £17.10 − £8 | £9.10 |

注意区分三个量：

- **采购支出**是已经付出的现金，可能包含尚未卖出的商品。
- **已售成本**只属于已付款交易，剩货继续保留库存价值；毛利不能简单用收入减掉全部提前备货支出。
- **扩容支出**单独记录，不改变商品交易毛利，也不能在日结时再次扣款。已日结后购买扩容，日结信息应同步反映该笔投资。

日结条件是当日三单已付款、最后顾客已离店、无未完成结账货物。日结只是锁定汇总；重复点击不刷钱。进入次日承接原现金、库存和容量，不重置商品身份，不新增 £12 本金。

本轮只有一次 £8 的**货位容量**升级，没有第二档、新家具购买或房间扩建。已经升级时应明确显示“已扩容”；钱不足应显示差额。高级服务与自动化仍遵循后续“资金 + 对应英语任务”规划，但尚未实装，不能冒充本轮可买能力。

## 语音与鼠标

### 顾客和商品音频

- 入店：`Hello!`
- 结账：`Can I pay by card, please?`
- 成功付款后：`Thank you. Have a lovely day!`
- R / “重听”：重播当前顾客台词。
- “请再说一遍”：播放 `Could you say that again, please?`，接慢速重播，帮助玩家看见请求重复的用法。
- 商品近看：“听单词”使用原有 milk / bread 真人录音；“听搭配”使用完整的 `A carton of milk.` / `A loaf of bread.` 合成短句，不拿一个单词冒充整句。

八条短句资产的台词与路径统一定义在 `src/sim3d/speechClips.ts`；资源清单也含肯定回应和刷卡句变式。文件存在不等于已经做了自由回答、错误判定或全部教学流程。语音属于预制资源，不调用运行时 LLM，不请求麦克风，也不评估玩家口音或自由口语。

首次用户点击开始后进入自动播报流程；浏览器如拦截播放，显示可手动重听的入口与实际错误状态，而不是假装播放完成。自动播报与连续重听已在真实浏览器验证；关闭自动语音、静音、拒播与暂停中止另有事件回归测试。字幕与按钮不以本机是否装有英语声线为前提。

顾客短句为**本地英式合成语音**，不是真人为本游戏配音。八条共 636,230 字节，Cori 模型来源和公开分发依据见 [phrase-SOURCES.md](../public/assets/sim3d/audio/phrase-SOURCES.md)。两条真人词音频仍按 [audio-SOURCES.md](../public/assets/sim3d/audio/audio-SOURCES.md)署名。没有把约 63.5 MB 模型或 Python 运行环境装入网页。声音是否自然、语速是否舒服由用户试听确认；波形检查不能代替听评。

### 控制模式

| 输入 / 状态 | 行为 |
| --- | --- |
| WASD / 方向键 | 移动 |
| 鼠标捕获可用 | 鼠标转头；Tab 可主动释放 |
| 鼠标未捕获或不支持捕获 | 按住画面拖动转头，IJKL 备用；页面按钮可点 |
| Tab | 切换可点击鼠标 / 申请转头捕获，不为此主动暂停营业 |
| E / F / G | 上下文互动 / 近看或返回 / 安全放下 |
| R | 当前顾客台词重听 |
| B / U | 进货 / 普通扩容 |
| 收银互动 | 自动释放鼠标，不自动打开暂停菜单 |
| 管理面板 | 暂停顾客，清理移动输入；返回保持鼠标可点击，玩家自己按 Tab 切回 |
| Esc / 页面失焦 | 暂停或退出当前查看，清理按键与控制状态 |

“释放鼠标”和“暂停世界”是两件事：前者解决点击，后者给玩家安全阅读管理页的时间。不能因为单纯释放鼠标而意外冻结每次语音互动，也不能在关闭管理页时未经玩家动作抢回鼠标。

## 存档兼容与恢复

- 新键：`english-high-street:sim3d:v4`，备份为同名 `:backup`。
- 旧 v3 主档和备份只作为校验后的迁移源，原键不写、不删。迁移保留旧库存、现金、交易、已扫描商品和扩容，不补发首日本金。
- 若恢复旧备份或从损坏的新档回退旧进度，必须提示可能失去最新进度；不能将这种回退伪装成最新存档完全恢复。
- JSON 导入先校验版本、货物、交易和金额，再由玩家确认替换；无效文件不改变当前进度。旧 2D 存档不能当作 3D 导入。
- 同一来源使用单写入者保护。只读页不能采购、收款或扩容；先关闭另一写入页，再使用“读取最新进度并尝试接管”，不要通过重开新档绕过冲突。
- [历史 2D 入口](http://localhost:4200/?legacy=1)和存档仍独立保留；[S0 历史记录](./S0_3D_IMPLEMENTATION.md)不改写为 S1 的验收记录。

已在内置浏览器实际完成的顺利路径：

1. 从独立测试新档开始，用 £12 买三份，确认现金 £5.10、两种货各三件。
2. 搬运上架、营业牌开门，三位顾客自动接续；在指定阶段出现正确字幕和本地语音。
3. 使用拖动/IJKL 回退控制，实际按 R 重听、点击请求重说，收银后按钮仍可操作；系统级鼠标捕获并非本次内嵌浏览器实测结论。
4. 三单逐件扫码并付款、最后一位离店，日结 £12 收入、£6.90 已售成本、£5.10 毛利、£17.10 现金。
5. U 购买普通扩容后 £9.10、每种货位八格；进入次日并刷新，库存、资金和扩容完整保留，不再给本金。

另在次日采购 1 份，资金变为 £6.80、库存 2 件；再次刷新后保留第 2 天、£6.80、2 件库存和每种 8 个货位。测试使用独立来源，未覆盖用户 localhost:4200 的实际进度。代表性页面没有发现控制台运行错误或缺失的游戏资产。

语音验证读取实际媒体的 `currentSrc`、`ended`、`paused` 和速率，而非仅看“播放结束”文案。发现并修复了媒体更换 `src` 后将 `playbackRate` 重置为 1 的问题：同时设置默认速率、当前速率并在加载元数据时校正；现已真实验证慢播为 0.84，下一句正常播报恢复为 1。重复请求结束前打开管理/切换语音时，过期回调不能修改新的音频。

收尾审查还覆盖了“请求重复尚未播完就按 R”的中断路径：顾客音频及英中字幕一同恢复，不遗留玩家请求句字幕；过期结束事件不能触发新的慢播。该路径同时加入事件单测和真实浏览器回归。

领域与事件测试覆盖的异常和恢复分支（不冒充全部经过实体设备点击）：

- 资金不足、已购扩容、重复采购单、重复付款/日结、未完成三单就日结：不改错现金或库存，有原因提示。
- 先升级再进货、额外提前备货、携带商品时打开管理页：经济与物品一致，成本和库存价值不混淆。
- 语音播放失败、快速重听、请求重说中途暂停/失焦/离页：无叠音、无假完成、可恢复。
- 单纯 Tab 释放、浏览器拒绝捕获、收银自动释放、关闭管理页：不死锁、不误走动、不擅自重新捕获。
- 在采购后、扫码中、付款后、日结后刷新；迁移正常/损坏 v3、无效导入、只读多标签冲突：恢复可说明，不覆盖旧键，不重复发本金。

跨浏览器、持续帧率、1% low、普通 Windows 设备、正式美术和教师审核应按实际完成情况分别记录。没有做的保持未验证；不能由某一瞬时帧率或一次顺利试玩推断全部通过。
