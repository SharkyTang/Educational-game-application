# 现金第四版：实体钱箱与可见货币

现金前三版已经建立现金收款、有限零钱库存、备用金调配、当天整单退款与打烊盘点，历史范围和验收记录见 [现金收款与管理](./CASH_PAYMENT.md)。第四版把这些已有状态显示为三维钱箱、硬币、纸币和托盘，让玩家能看见正在收取和找出的现金。

第四版已在电脑／循环配送提交 `53c59fc` 的 v15 基线上完成。资产、状态投影、场景钱箱、现金近景和宿主控制器已经接通；完整 `npm run check` 通过 1845 项单元测试、类型检查与生产构建，完整 57 项 Chromium 浏览器回归全部通过，单 worker、零重试。最终验收于 2026-09-09 完成。

## 本版范围

### 可见钱箱和教学英镑

- 钱箱具有固定外壳、可沿收银员方向滑出的抽屉及十个分格。后排为 £5、£10 两种纸币，前排两行放置 1p、2p、5p、10p、20p、50p、£1、£2 八种硬币。
- 盒体宽 0.52 米、深 0.40 米、高 0.075 米，抽屉最大滑出 0.27 米。资产原点位于盒体中心，`+z` 指向收银员；现有 POS 支架仍位于固定外壳上方。
- 硬币采用铜色、银色和双色材质，并标出面额。纸币显示大面额和 `PLAY MONEY`，使用程序化几何及文字贴图，不复制真实钞票图像。
- 创建钱箱资产只生成空盒和分格。可见货币必须由当前存档投影提供，模型不会自动补发备用金或生成交易。

### 真实场景与现金近景

实体钱箱替换原收银台上的静态 `counter-drawer` 装饰盒，绑定为真实收银台的子对象。店内装修移动或旋转收银台时，钱箱、交款区和找零托盘一起移动；这些显示不额外占据商品货位，也不形成第二个收款入口。世界绑定已通过四向旋转和两件商品最大摆放范围的几何测试。

玩家仍需走近收银台，并扫描完本单商品，才能打开现金收银。已有现金面板内增加同一钱箱的三维近景，提供三个明确区域：

1. **顾客交款区**：显示本次顾客提供的面额。点取该区相当于现有“收下现金”操作，收下后标为暂收；正式完成付款前不能放入可找零库存。
2. **钱箱分格**：显示扣除当前托盘预留后的可用数量。收下现金并打开钱箱后，点一个可用分格或该分格的可见钱币，加入一枚／张找零。
3. **找零托盘**：显示当前已选零钱。点击可见钱币可以撤回对应的一枚／张，实际顺序和金额仍取自原付款状态。

确认完成收款继续使用现有确认按钮和金额校验，确认按钮与找零反馈放在本单金额卡中。近景旁另以清晰文字显示应找、已选、还差／多了的金额。抽屉开合只改变展示；合上抽屉、关闭近景或暂时离开收银，不清空暂收款和已选找零。当前顾客、扫描进度、找零是否足够、写入权限等条件仍由原收银控制器和领域命令检查。

近景保持固定相机，避免拖动画面时意外收钱。按钮提供完整文字说明与金额反馈；画布内的模型、数量标签和操作权限全部从同一份付款状态派生。

## 显示数量与账本的关系

每个区域内的每个面额堆最多绘制 **6 枚／张示意**，标签显示该堆对应的真实数量。这不是把库存限制为六枚，也不是把原付款状态截断。

- 钱箱标签表示当前可点取数量，即存档内的钱箱库存减去找零托盘已经预留的同面额数量。
- 顾客交款区与找零托盘按面额分组，但保留完整交款数组、找零数组和对应索引。超过可见样本的零钱仍保存在本单中，玩家可用面额按钮和完整辅助列表逐项处理。
- 原来的单次交款／找零最多 100 枚／张规则继续有效，三维显示不会扩大该上限。
- 顾客暂收款只有在确认收款成功后才进入钱箱；找零也在同一次正式提交中扣除。显示模型不能提前改变面额库存或经营收入。
- 对旧档中按总金额推导的交款组合，近景明确提示“旧版未记录面额，以下按金额推导示意”，不会冒称历史上实际递交了这些钱币。

## 输入、降级与存档

面额按钮、找零辅助列表、重听、零钱不足处理及确认收款按钮继续保留，键盘用户无需依赖三维画布。3D 点取调用的是已有的 `RECEIVE_CASH`、`ADD_CHANGE`、`REMOVE_CHANGE` 命令；模型元数据只描述外观，不授予收款或找零权限。

近景画布使用独立渲染实例，最多每秒绘制 30 帧。关闭近景时释放该实例，下一次主动打开时按最新状态重新创建；后台或画布离开页面时暂停绘制。游戏中的“减少动态效果”与操作系统的对应偏好任一开启时，抽屉直接到达目标位置。若 WebGL 不可用、渲染失败或绘图上下文丢失，界面隐藏近景并立即恢复面额按钮（即使失效前刚合上钱箱），付款和找零状态保留。

第四版是现有现金状态的显示层，**不新增 v16 存档，不修改 schema，也不建立第二套账本**。当前项目已有的 v15 存档以及此前现金审计字段继续由原领域与持久化流程维护；抽屉开合、可见样本数量、动画进度和画布资源不写入经营账本。现金／刷卡混合经营、退款、备用金调配、盘点和旧档迁移规则见 [前三版现金说明](./CASH_PAYMENT.md)。

## 不包含的表现与玩法

本版有可开合钱箱和可见货币，暂不包含顾客或玩家手部抓取、伸手递钱、逐枚放钱的骨骼动画，也不模拟硬币抛落、散落碰撞等物理效果。交款区与找零托盘的位置变化不等于已经完成手部递交动画。

部分／跨日退款、真实银行卡支付、验钞、小费、混合付款、顾客耐心惩罚等不因三维显示而加入。是否需要这些后续内容，应按实际游戏需求另行确定。

## 模块

- `src/sim3d/cashVisualAssets.ts`：空钱箱、分格和教学货币资产；独立 NullEngine 专项已覆盖十个空格、实际尺寸、滑动范围、底部堆叠锚点、文字标识、材质差异及两实例独立释放。
- `src/sim3d/cashVisualState.ts`：从现有钱箱与付款状态派生显示数量和允许点取的动作；不修改输入存档。
- `src/sim3d/cashDrawerVisual.ts`：场景中的钱箱、交款区、找零托盘、数量标签与有界样本；已有独立 NullEngine 测试。
- `src/sim3d/cashVisualViewport.ts` 与 `.css`：现金面板内的近景、开合控制、生命周期与按钮回退；已有独立生命周期测试。
- 真实 `World`／`App3D`／收银控制器宿主接线：绑定原收银台与当前付款，负责打开／关闭、实时权限复核、游戏动画偏好和失败时恢复辅助按钮。

开发阶段的单模块通过记录，只说明各自测试覆盖的行为。此前现金前三版的浏览器测试数量不属于本次第四版验证结果。

## 性能与视觉复核注意点

“每堆六枚”是单个面额、单个区域的显示上限。极端情况下，钱箱、交款区和找零区都可能具有多个面额堆，场景与近景也可能同时各持有一份模型，因此仍需在目标设备上检查总绘制成本和文字贴图占用。未活动的样本可隐藏复用，关闭近景后的资源应可回收，不能单凭上限规则宣称性能已经验收。

相机和盒体经过几何检查，桌面与窄屏开发实测修正了文字方向、标签可读性及前排 50p 硬币被标签遮挡的问题；新增三种窄画布宽度、四种前排硬币共 12 次真实币面中心命中回归。最终视觉仍以实际浏览器截图与真实点击为准，不用模型元数据代替视觉检查。
