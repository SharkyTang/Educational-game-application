# 店内电脑与当日循环经营

本轮把经营流程串成「少量进货 → 售出回款 → 当天再次补货 → 持续接客 → 到点打烊」，并把六个管理入口集中到店内实体电脑。本文是当前电脑入口、配送、营业节奏和 v15 存档规则的说明；早期文档中的 7 分钟营业、8–12 秒来客间隔、每日统一送货及电脑外 B / U / P / M 入口已经被本轮替代。

## 从少量本金开始

1. 新档有 £12 本金，电脑桌免费提供。先找到门内左侧、橱窗与收银区之间的木桌，走近并看向显示器，按 E 打开电脑。
2. 点击「进货」，从全部 30 种商品中选择种类与数量。可按分类或中英文名称搜索；默认数量都是 0，不会自动勾选或扣款。确认前显示总价、可用资金及容量限制。
3. 确认订单后扣款，并自动退出电脑。货车空闲时，本单正常约需 12 个有效秒到店；HUD 会显示备货、驶入或排队状态。不要停留在电脑里等车，因为电脑会暂停配送。
4. 货车停稳后，空手靠近并看向车辆，按 E 签收当前这一单。然后搬箱上架。至少一种商品有货架库存后，可在电脑「营业 / 日结」点击开门，或到实体营业牌按 E 开门。
5. 完成销售后，可以立即回电脑用所得资金下第二、第三笔订单，再签收和上架。每天不限制采购次数、签收次数或顾客总人数；余额、容量和打烊状态仍会限制下单。
6. 收尾结束后，按提示回电脑完成日结。现金、未售库存、设备和升级带入次日；日结不重复发放已经入账的销售收入。

缺货时先看提示：货架没有商品但箱内有货，需要上架；商品在途中，需要等待并签收；库存售空，才需要回电脑采购。无需为了等补货而结束当天营业。

## 六个桌面应用

电脑桌面显示店铺名称、日期与营业钟、资金及配送状态，图标使用同一套绘制的图形与文字标签。每次打开一个应用，复用已有管理操作与确认流程。

| 图标 | 功能 | 电脑内快捷键 |
| --- | --- | --- |
| 进货 | 30 种商品清单、分类与搜索、数量、总价、已付订单和配送进度 | B |
| 营业 / 日结 | 开门、提前打烊、营业账本、日结和开始次日；「现金管理」子页保留备用金、退款及盘点 | — |
| 扩容 | £8 普通货架扩容；「店铺成长」子页保留等级、成就与实体扩建 | U |
| 设备商店 | 设备购买、已拥有设备和仓库 | — |
| 装修 | 现有家具、设备和电脑桌的选择、移动、90°旋转与应用布局 | P |
| 商业街 | 咖啡店、餐厅、大商超的介绍、等级、成就及开放条件 | M |

打开电脑须由真实近身互动建立会话；站在远处按快捷键、打开普通暂停菜单或点击通知，都不能进入经营应用。进入电脑前手持的货箱或商品会保留，但装修仍需满足双手空闲、店内无顾客且处于准备或已日结阶段等原有条件。

- 应用窗口提供「返回桌面」与「退出电脑」。应用内按 Esc 返回桌面，桌面按 Esc 退出电脑。
- 未应用的装修草稿会先提示保留或放弃，切换应用或退出电脑也不会静默丢弃。布局中的 R 仍用于旋转。
- B / U / P / M 仅在电脑会话内切换应用；输入框、搜索框、数量框、选择框或可编辑文本获得焦点时，不触发应用快捷键。
- 电脑外按 Esc 打开普通暂停菜单，其中保留设置、帮助及「存档与试玩管理」。HUD 保留时间、资金、库存、配送和目标互动提示，原来的六块常驻经营按钮已移除。
- 实体营业牌保留准备期的开门动作，营业中只提示状态；商业街门牌只读介绍；货车只办理当前订单签收。它们不提供管理导航。
- 日结条件满足时只提示「到电脑完成日结」，不自动打开应用。下单成功会自动退出电脑，避免配送被管理界面一直暂停。

## 一辆车逐单配送

配送按已付款采购记录的顺序处理，流程为：

**下单扣款 → 排队 → 6 秒备货 → 6 秒驶入 → 停稳等待签收 → 本单卸货 → 4 秒驶离 → 下一单。**

这里的秒数都是有效配送时间。12 秒指货车开始处理本单至正常停稳的时间，不包含前方订单、等待玩家签收、暂停或挡车时间。排队订单显示前方订单数，不承诺全部订单同时到达。

- 空闲货车立即开始最早未签收订单。到达后停稳等待，签收只处理当前订单的商品和回收批次；后续订单仍然在途，不会随第一单一起入库。
- 签收后货车需要约 4 秒驶离，才能处理下一单。即使最后一单商品已入库，日结仍需等车辆离开。
- 同一种商品连续补货沿用已有货箱位置；容量检查把待送商品也算入，不能通过连续下单超出容量。
- 货款在下单确认时扣除，不在签收或刷新时重复扣款。同品合箱不额外制造回收奖励，回收仍按实际货箱与已记录来源计算。
- 玩家挡在行驶路径时，车辆及这一段配送进度同步暂停，HUD 提示让行；离开车道后继续。停稳待签收不靠计时自动卸货。
- 在准备期、营业期与打烊收尾期都能配送。打烊停止新采购，但打烊前已付款的订单仍会逐一送完。

## 营业钟、配送钟与顾客

准备期营业钟停在 08:30，不限时。手动开门后从 09:00 开始，累计 **720,000 毫秒有效营业时间，即 12 分钟**，走到 19:00。暂停、管理与学习用时不消耗这个营业日；准备和收尾也不算入 12 分钟。

| 状态 | 营业钟 | 配送 |
| --- | --- | --- |
| 准备期在店内活动 | 停在 08:30 | 继续 |
| 营业期走动、搬货、上架、扫码 | 继续 | 继续 |
| 正常现金收银 | 继续；19:00 不打断当前交易 | 继续，人物动作暂停 |
| 打烊收尾期 | 不再推进营业时间 | 已付订单继续 |
| 电脑、普通暂停、近看学习、街头邻居对话 | 暂停 | 暂停 |
| 主动重听或慢读 | 播放期间暂停，结束、停止或失败后恢复 | 同步暂停与恢复 |
| 后台、失焦、隐藏页面或只读标签 | 暂停 | 暂停 |
| 仅按 Tab 释放鼠标 | 继续 | 继续 |

普通顾客台词仍正常播放，不把每句自动问候都当作学习暂停。主动重听和慢读才使用学习暂停。返回游戏与刷新均不补算离线时间，也不补发收入。

每天顾客总人数不限，同时仍接待一位。第一位从开门后开始来店；后续必须等上一位真正离开，间隔 **2–4 秒**再安排新客。顾客仍从街道左右远处走来，因此这个间隔不是直接出现在店内的倒计时。

| 动作 | 本轮参数 |
| --- | --- |
| 街道行走 | 2.2 米/秒 |
| 店内购物、店内离店路段 | 1.7 米/秒 |
| 取货节点停顿 | 0.2 秒 |

行走动画随区域步速调整，顾客离开店门进入街道后使用街道步速。没有货架库存时停止安排新顾客，已有顾客与订单不会被强行替换；补货上架后，若尚未打烊，会自动恢复客流。缺货期间营业钟继续。

18:30 提醒即将打烊，19:00 停止新顾客和新采购，也可以在电脑确认提前打烊。当前顾客可以完成结账或安全取消订单。**最后一位顾客离开、待付款商品处理完、全部配送签收且货车驶离**后，才能到电脑日结。若只剩最后一辆车离场，提示会明确说明等待驶离，不误说还有顾客未结账。

## 电脑桌与装修

电脑桌是一件独立家具，木桌、显示器、主机、键盘和鼠标作为整体制作。桌面占地约 **1.2 × 0.55 米**，新档默认位于门内左侧，屏幕朝店内。新档和迁移旧档均免费获得，不扣本金，不当作货架，不增加任何商品容量。

在电脑「装修」中可以选择电脑桌，按原有规则拖动或用方向键移动，按 R 做 90°旋转，确认「应用布局」后生效。桌体、显示器、碰撞与屏幕互动位置同步更新。电脑不能出售、删除或收入设备仓库，以免玩家失去经营入口。

应用布局时同时检查家具重叠、边界、入口、收银与货架通道，以及电脑正面的操作空间。不能把电脑摆到看得到却走不到的位置。正在营业时可查看装修，但移动设备仍遵守准备期或已日结阶段的条件；保留的手持物品需先放下。

## v15 存档与旧店安置

当前存档版本为 **v15**，在 v14 现金管理基础上增加可保存的配送状态和独立电脑布局。

- v3–v14 存档先按各自原版规则校验，再依次迁移，不用新的 12 分钟范围倒推旧存档是否合法。迁移失败时不覆盖原始存档。
- 旧营业时间按比例换算，钟面保持一致：旧档显示 14:00，升级后仍是 14:00。已经打烊或日结的状态不会重新开门。
- 已安排顾客的剩余等待保留原先已完成的进度，剩余最多缩为 4 秒；当前顾客、商品和已发生交易不重建。
- 最早一笔旧未签收订单恢复为待签收，之后的未签收订单按原顺序排队；已经签收的订单不会重新配送。
- 电脑优先放默认位置；若被原家具占用，按固定规则寻找合法室内位置，包含扩建和自定义布局。
- 极满的旧布局使用门外左侧固定预留临时位，仍须走近屏幕按 E 操作，不增加远程入口。腾出室内空间后可在装修中搬回；该位置不代表开放任意室外摆放。
- 保留旧家具、商品、交易、钱箱、退款、备用金、盘点、扩建、成就及日结记录。沿用上一有效快照、JSON 导入导出、多标签写入保护与写入失败提示。

配送保存当前订单 ID、阶段（空闲 / 备货 / 驶入 / 待签收 / 驶离）、阶段内有效时间及挡车状态。车辆位置由同一份配送状态计算，刷新后不会出现逻辑已到货、车辆却重新出发的问题。签收命令必须对应当前已到达订单，不能跳过队列或重复发货。
