# 顾客外形与常用语料库

本文记录顾客外形与语料库。现金第一版在原有顾客变化上补入现金请求与交款金额，付款规则另见 [现金收款](./CASH_PAYMENT.md)；不新增购物袋或自由对话。

## 范围

- 6 个独立成人购物顾客外形：3 男、3 女；不是同一女模型换衣服颜色。另有 2 个独立成人模型预留给具名街头邻居，不进入购物顾客池。
- 顾客移动速度从 0.94 m/s 提升至 1.41 m/s（+50%），行走动画同步加快。
- 低帧率下按真实时间计算顾客位移，拆成最多 0.05 秒的小步；单帧最多追赶 0.25 秒，仍保留暂停和玩家挡路时的避让。本次顾客改动未调整玩家与货车；玩家后续提速规则见 [玩家移动与加速](PLAYER_MOVEMENT.md)。
- 阶段停顿由 1.1 秒缩短至 0.35 秒，离店末尾只保留 0.1 秒；当前营业时间版在上一位真正离店后，按保存种子等待8—12秒再接下一位，同时仍只有一位顾客。当前接客与暂停规则见 [营业时间第一版](./BUSINESS_TIME.md)，下方素材版本验收保留历史口径。
- 45 条短句：进店问候 11 条、刷卡结账 14 条、现金请求 6 条、交款金额 3 条、付款后道谢 11 条。每条都有英文、中文与男女两套本地音频，共 90 个 WAV；v1 的 70 段录音逐文件保持不变。
- 原有单词录音、商品搭配发音、玩家请求重复等素材保留。配音是离线生成的合成声音，不称为真人演员录音，也不在玩家设备上运行语音模型。

## 怎样随机，又不影响重听

新一轮游戏生成一个 `customerSeed`，点击开始营业时随首次进度一起保存；仅打开加载页或加载失败不会新建存档。之后按这个种子、顾客序号和场景分别选取外形及短句：

1. 将同场景的语句打乱，轮完一遍再重新打乱；相邻两轮的边界也避免连续重复。
2. v2 外形使用同一原则，每轮 6 位顾客会覆盖全部购物外形；任意连续一轮都包含 3 个男声和 3 个女声。
3. 台词不在每次画面刷新时重新抽取。同一位顾客的重听、慢速重复、暂停恢复和存档导入沿用同一组选择。
4. `customer.contentVersion` 固定当前访客使用的素材池：v1 严格保留原 4 个外形和每个场景原来的语料长度，v2 才启用 6 个外形与新增 10 句。旧存档缺少字段时迁移为 v1，新游戏使用 v2；不会为了增加角色而让已在途顾客换脸、换台词，也不会清空库存、资金或交易记录。

这仍是分场景的预制台词库，不是麦克风识别、自由聊天或大模型实时生成对话。

## 以后怎样补充台词

单一文本源是 [customerCorpus.json](../src/sim3d/customerCorpus.json)：

```json
{
  "id": "checkout-can-i-pay-by-card",
  "text": "Can I pay by card, please?",
  "zh": "请问可以刷卡吗？"
}
```

将新条目加入对应的 `greeting`、`checkout`、`checkoutCash`、`tenderCash` 或 `thanks` 数组，保持 ID 唯一且只使用小写英文字母与连字符。短句必须与实际动作相符：现金请求仅供现金顾客使用，交款短句与本次保存的金额对应；尚未付款时，不播放道谢离店句。£5、£10 使用对应金额录音，其他刚好付清的金额用“I have the exact amount.”。

更新后使用 [配音生成脚本](../scripts/generate-customer-speech.py)生成男女两套音频，并同步更新生成清单；`--reuse-existing` 校验并保留已有录音，只生成新增条目。模型准备、下载校验与命令见 [配音来源说明](../public/assets/sim3d/audio/customer-phrase-SOURCES.md)。只改文字而不重新配音会被素材一致性检查拦住。

## 代码入口

| 文件 | 职责 |
| --- | --- |
| `src/sim3d/customerCorpus.json` | 场景、英文与中文语料 |
| `src/sim3d/customerSelection.ts` | 6 位购物顾客资料、v1/v2 兼容池、保存的种子、无连续重复选句、移动参数 |
| `src/sim3d/customerActors.ts` | 缓存独立模型、切换显示、对应行走与站立动画 |
| `src/sim3d/App3D.ts` | 名称、字幕、自动配音、重听与慢播的实际交互 |
| `src/sim3d/world.ts` | 真实场景中的路线与移动 |

库存与交易的账本校验继续由 `domain.ts`、`persistence.ts` 负责。`customerSeed` 用于外形、台词及入店时的付款选择，不会改动商品售价或凭空发放库存与资金。

## 验证边界

单元检查覆盖语料完整性、随机不重复、跨存档稳定性、模型启停与本地音频文件一致性；浏览器回归覆盖真实加载、抵达收银台、重听/慢播和付款。模型外观、步态与配音自然度仍需结合实际画面和试听判断，文件哈希或 WAV 波形检查不能替代主观听评。
